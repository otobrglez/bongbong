# Minigun Bullet Sprite Sheet — Integration Notes

`minigun_bullets.png`, the individually-simulated projectile fired in bursts
by a tank holding minigun ammo (see `bullet.rs`, `pickup::PickupKind::Minigun`).

---

## 1. Overview

| | |
|---|---|
| Dimensions | 96 × 32 |
| Grid | 3 cols × 1 row |
| Cell size | 32 × 32 |
| Variants | 1 (no chassis-colour rows, unlike `shells.png`'s 18) |

Every bullet, regardless of which tank fired it, draws from the same single
row — `bullet::Bullet` has no `variant`/`shooter_row`-indexed colour field
the way `Shell` does. The minigun's visual identity is the tracer itself,
not a chassis-matched recolor.

---

## 2. Column layout

| Col | `BulletState` | Meaning |
|---|---|---|
| 0 | `Muzzle` | Tiny spark as the round clears the barrel |
| 1 | `Flying` | Tracer in the air |
| 2 | `Hit` | Small impact spark |

Three states, not `ShellState`'s seven — bullets fire far too rapidly in
succession (`MINIGUN_BULLET_DELAY_SECONDS`, ~0.04s apart) for an elaborate
multi-frame wind-up/impact sequence to read well at burst cadence. `Muzzle`
and `Hit` are both short, single-beat flashes (0.025s / 0.08s) rather than
`Shell`'s three-frame fire sequence and three-frame impact sequence.

---

## 3. Why a separate sheet, not more `shells.png` rows

`docs/SHELLS_SPEC.md` §1/§7 documents "the column layout is untouched, all
seven `ShellState` columns keep their existing meaning and index" as a hard
invariant of that sheet — appending rows works only because every row still
follows the same 7-column shape. A bullet's 3-state machine doesn't fit
inside that shape, so it gets its own sheet, its own `BulletState` enum,
and its own `bullet.rs` module rather than being shoehorned into `Shell`.

---

## 4. Sizing

Drawn roughly a third the linear size of `shells.png`'s `std` single-barrel
class within the same 32×32 cell (so it still scales via the same
`TEXTURE_SIZE * SCALE` convention as every other sprite, just occupying much
less of that cell) — a light, fast round rather than a lobbed shell:

| Shape | shells.png `std` | minigun_bullets.png |
|---|---|---|
| `projectile()` nose height | 3 | 1 |
| `projectile()` body height | 8 | 3 |
| `projectile()` width | 4 | 2 |

`Muzzle`/`Hit` are single layered discs with short cardinal rays (no smoke,
no multi-ring detail) — a bullet impact reads as a tick, not a lingering
detonation.

---

## 5. Style

Generated by `tools/spritegen/gen_bullets.py`, reusing `gen_shells.py`'s own
drawing primitives (`blank`/`put`/`disc`/`rays`/`projectile`, copied in
rather than imported — no generator script imports another's primitives,
only `punypalette` is shared) at smaller parameters. Palette: casing colours
identical to `shells.png` (`STONE_DK`/`STONE_LT`), tracer colour `WOOD_LT`
(the same warm bronze-gold family as `shells.png`'s `NOSE` tone, for a "hot
metal" kinship with shells without being identical).

Regenerate in place with:

```
nix-shell -p "python3.withPackages (ps: [ps.pillow])" \
  --run "SPRITE_OUT=static python3 tools/spritegen/gen_bullets.py"
```

## 7. Not changed

- `ShellState`, `Shell`, `shells.png` — entirely untouched by this sheet.
- The turret-mounted minigun overlay (`static/minigun_mount.png`,
  `tools/spritegen/gen_minigun_mount.py`) is a separate, single-tile
  texture, not part of this sheet — see `docs/SPRITESHEET_SPEC.md`'s
  composition-order section.
