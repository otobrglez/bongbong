# bongbong

Bongbong is a tank shooter: fast, fun, pixelated in the spirit of old arcade tank games, with semi-realistic physics, challenging AI and a built-in battlefield builder.

**This file is loaded into every session, so it stays under 40k characters.** It holds the rules, the invariants every change must keep and where to look. The detail is in three references, read on demand - `docs/codebase.md` (module by module), `docs/tooling.md` (tests, probe, dev servers, assets) and `docs/platforms.md` (room server, web, iOS, Android, releases) - and in the design doc each module names. A change updates the reference entry and the design doc for what it touches; this file changes only when an invariant does, as a line in the existing bullet, never a new paragraph.

# Development rules (Linear)

These MUST be followed. Where one cannot be, **ask Oto to bypass it** and wait for the answer; never take the exception silently.

- **No work that Linear does not trace.** Anything that changes the repository, the Linear workspace, a deployment or a release belongs to a Linear issue (team **BongBong**, key `BB`, `linear.app/bongbong`, the `linear-server` MCP tools). Use the issue if one exists (search first); otherwise file one before starting (the `linear-file` skill). Answering a question or reading code changes nothing and needs none.
- **Starting work sets the issue to In Progress** (assigned to `me`), before the first edit, **and comments the session** so Oto can resume it: `$CLAUDE_CODE_SESSION_ID`, the working directory and `cd <dir> && claude --resume <id>` (sessions are kept per directory, so a worktree's is its own), once per session that works on the issue.
- **Needing a human sets it to AI Blocked** - a question, a clarification, an approval (to commit, open a PR, deploy, take an exception, choose between options), or finished work waiting for review - with a comment on the issue saying exactly what is needed, ending with the resume line. Back to In Progress when the answer comes.
- **A PR open with its CI green sets it to In Review** - the session does it once every check has passed (`gh pr checks <N> --watch`), since the GitHub integration does not; a red check keeps it In Progress until fixed, and review feedback takes it back to In Progress until the next green push.

How the work is done is the `linear-issue` skill: the branch is the issue's `gitBranchName`, the commit subject and PR title are `<what changed> (BB-N)`, and the PR body opens with `Fixes BB-N` for each issue it finishes (`Part of BB-N` links without closing); the GitHub integration moves the issue to Done when the PR merges, so nothing sets Done by hand. Labels: one type (`Feature`, `Bug`, `Improvement`) plus areas (`gameplay`, `Maps`, `HUD`, `Design`, `server`, `security`). Work found outside the issue in hand is filed as its own issue, not folded into the PR.

# Architecture & environment

- Rust, edition 2024. raylib through the `sola-raylib` bindings (source and examples in `../sola-raylib`, raylib's C source in `../raylib`), `rapier2d` for physics (`../rapier`), `hecs` as the ECS. Everything has to compile to wasm - the web is a main distribution channel.
- Features: `render` (raylib and everything that draws; default), `online` (the client's WebSocket; default), `dev-tools` (dev server, `capi`, debug overlays, the web tuning panel), `touch-steer-right` (the stick on the right; a recompile, not a knob). `--no-default-features` is the headless crate - simulation, probe, tests, room server - with no C compiler, cmake or raylib (`cargo tree --no-default-features -e normal | grep sola` is empty); only the server image and CI's bare check build it.
- devenv (Nix): `devenv.nix` pins Rust, its targets (wasm, iOS, Android) and the tools; `.envrc` holds credentials. Run everything from the devenv shell. `just --list` names every recipe; README.md has the per-platform setup/run table.
- Dev loop: `just watch`, `just run-dev` (dev-tools build with the dev server), `just run-editor` (start in the builder). Options: `-e/--enemies`, `-m/--map` (free play on that map), `--level N|NAME`, `--tank`, `--seed` (decimal or 0x-hex), `--editor`, `--players`, `--tank2`, `--mission`/`--spawn`/`--waves*`/`--tier-*`, `--tuning <file>`, `--resolution`, `--fullscreen`, `--zoom`, `--touch-from-mouse`, `--weather`, `--lang`, `--map-modding false` (SAVE writes `maps/`); online: `--rig` with `--delay`/`--jitter`/`--loss`, `--host`/`--join CODE` with `--nick`/`--rooms`.

## Module map

One line per module: what it owns, the rule to keep, its design doc. **Before changing a module read its entry in `docs/codebase.md` and the doc it names.**

**App, session, data**
- `app.rs` — the raylib handle, the main loop and the only raylib input reading. Play runs `Game::update` in whole `PHYSICS_FIXED_DT` steps (`StepClock`: at most 4 a frame, a frame with no step carries its presses on); Build, Lobby, Online and the level select are the other paths. HUD buttons and dialogs are hit-tested before input is gathered, and a dialog freezes the round through `Session::playing()`, never a simulation flag. The field is the map's, the window anyone's (`view::View`, `Presentation::of`); on the web the page's `window.bb*` globals are read only here (`page_string`).
- `mode.rs` — `Session` owns the round, the builder, the dialogs, the campaign, the level select and a room's seat; `playing()` decides whether `update` runs; `shown()` is the round every drawing path and dev tool reads (the replica online). Levels, PLAY HERE and the clear check (docs/levels.md, docs/game-editor-fusion.md §5).
- `level.rs` (`Mission`, `SpawnKind`, `LevelOverrides`: CLI > map > tuning), `levels.rs` (`levels.toml`, `Campaign`, the progress store), `level_select.rs` - docs/levels.md. `training.rs` + `bubble.rs` - a training map's beat script and the frog's voice (docs/training-stage.md).
- `map.rs` — the TOML map format (docs/map-editor-design.md): 32 px cells, 8..=250 a side; hand-authored files write `mission.*`/`spawn.*` as **dotted keys** (a `[spawn]` header swallows every later `cells.` line); `iter_cells` sorts; `SHIPPED_MAPS` are embedded (all the web can list, all a room can open); `MapFile::class` decides arena (shown whole) or field (followed). An editor re-save drops header comments - edit fixtures by hand. `mapstore.rs` keeps the player's maps and modified copies (`<name>-modd`).
- `text.rs` — every string a player reads (docs/localization-prd.md): `text::keys` constants over `lang/<tag>.ftl`; no custom font, so `fold` maps letters onto Latin-1; `width`/`fit` measure; `every_language_fits_every_budget` fails a translation that overflows its box. Never `set_language` in a test; nothing under `simulation/` reads it.
- `tuning.rs` — the knob table (docs/runtime-tuning-design.md): `tunables!` rows read through `tuning()` (an `Arc` snapshot; bind once in hot loops). Writes are staged and applied only at the frame boundary (`apply_pending` before `Game::update`); derived values are methods, not rows.
- `math.rs` — `Vec2`/`Color`/`Rectangle`, arithmetic in raylib's order so replays keep their bits; add operations here, never through another vector library. `lib.rs` — layout constants and types only; its comments are the source of truth. `tank_art.rs` is generated - never edit it.

**Simulation** (`simulation/`: no raylib, no `text`)
- `mod.rs` — `Game`: `init`, and `update` as named phases over a per-frame `Frame`. Phases push `Event`s (tests assert on `game.events()`). A cause's cosmetic half is a `*_show` returning a `Spectacle`, shared with replicas so the two cannot drift. `tick_presentation` is a replica's cosmetic frame and is never called on a local round. `accept_seat_pose` validates a client-owned hull (docs/online-coop-prd.md §4.14).
- `hits.rs` — **the only projectile hit test** (a swept segment-vs-box; projectiles have no physics body); lag compensation rewinds enemy and frog boxes only, and a round with no seat views rewinds nothing. `weapons.rs` (fire dispatch shared by player and AI), `combat.rs` (hits, rams - pairs walked sorted), `engage.rs` (the engagement-slot ring), `portals.rs` (shots through portals), `debug.rs` (the dev-server surface; `debug_spawn_enemy` is the one mutator that draws RNG).
- World phases: `props.rs` (`damage_obstacle` the one place a tile loses health, `obstacle_died` the funnel every tile death passes; cosmetics hashed), `flame.rs` (no RNG), `missiles.rs`, `grenades.rs`, `towers.rs`, `volcano.rs`, `crates.rs` (off by default), `waves.rs` (gates; a rolling-in tank has no `Ai` until it arrives; a wrecked seat returns with the next wave), `field.rs` (field-map AI: chained alerts, leash, far tanks think less, spawns by walk, stragglers), `director.rs` (the wave breather), `training.rs`, `nav.rs` (the kept nav grid, held exact against a rebuild).
- The special weapons (BB-36) - sonic hammer, EMP, gauss rail, FPV swarm, rod from god, gravity well: each a world half in `simulation/<w>.rs`, a headless half in `<w>.rs` (data, measures, composers, its tuning group), a doc (docs/sonic-hammer.md, emp-burst.md, gauss-rail.md, fpv-swarm.md, rod-from-god.md, gravity-well.md) and `<w>_tests.rs`. Shared machinery: the wind-up tell and the AI hook (docs/sonic-hammer.md §3), the disabled state (EMP), the charge (gauss), air targets (`air.rs`), zones (`zone.rs`).
- `comms.rs`/`command.rs` — enemy command and control (docs/enemy-command-and-control-prd.md): draws no RNG, speaks `Intent` never `Ai`; `c2_enabled` defaults off, and off is byte-identical.
- `battlefield.rs` — boundary, gates, spawn placement: `enemy_spawn_legal` is the one legality predicate; `sample_clear_position` returns `None` on its cap - snap, never use a rejected sample. No procedural battlefield: a map is the only terrain source. `physics.rs` — the rapier wrapper (docs/physics-engine-design.md): solid bodies only; damping set only in `settle_wreck`; rapier's lengths are pixels (`length_unit` 1) with its speed cap and every hull's one-step look-ahead set in px, so hulls stop flush.

**AI**
- `ai.rs`, `bt.rs`, `pathfind.rs` — the AI reasons over snapshots, never the world. Stuck detection uses displacement along the commanded heading, never a physics velocity. An enemy fires at a seat only from inside that seat's sight box (`ai::in_sight_box`). A* plus per-target flow fields, ties on cell index, a portal hub; **`PATHFIND_CELL_SIZE` must equal `OBSTACLE_GRID_SIZE`**; a corridor needs 2 cells. The shared alert is deliberately a distance test with no line of sight (one re-opens the pile-ups) - re-baseline `just probe-fixtures` (`just probe-fields` on field maps) if you touch it.

**World entities** (state plus drawing generic over `canvas::Canvas`)
- `tank.rs` (12 chassis `TankKind`, a layered sprite about one pivot, owner slots, one special weapon at a time), `frog.rs` (bites only the other side), `pickup.rs` (supply crates; enemies collect only what they would use - `Tank::wants_pickup`, never stricter than seeking or a tank parks on a pickup), `obstacle.rs` (ask the predicates, never match `Material` variants; trees are 48 px art on 32 px cells, left out of seam-closing), `grass.rs` (**not an `Obstacle`** - the nav grid and linter treat every obstacle as impassable), `tower.rs`, `portal.rs`, `volcano.rs`/`lava.rs`/`lamp.rs`, `target.rs`.
- Projectiles: `shell.rs`/`bullet.rs`/`plasma.rs`/`laser.rs`/`missile.rs`/`grenade.rs` (`Owner::same_side` is the friendly-fire test; every projectile carries a per-round `id`).
- `ground.rs` — the Puny World floor and water's shape (docs/GROUND_SPEC.md, docs/water.md): deep water is a collider and a nav wall but never stops a shot; a ford slows and costs the router. `weather.rs` — the sky (docs/weather.md): rules (sight, grip, ice, gusts - each exactly 1 under a clear sky, so a clear round replays bit for bit) and the look; the sky is picked by a hash of the seed, never the round RNG.

**Drawing and effects** (read `Game`, never mutate it)
- `game.rs` paints the field through `canvas::Canvas` in three stages (floor, tiles, standing); `render/game.rs` is `Game::render`. `canvas.rs` — the drawing surface; `CpuCanvas` rasterises headless with trig through `trig.rs`, so pinned thumbnail hashes agree across platforms (docs/mapshot-prd.md).
- The effects language (docs/effects.md): `pyro.rs` - whole 2 px blocks, ramp steps, Bayer fades, which every explosion, hit, fire and smoke follows; pure composers `fireball.rs`, `burst.rs`, `mushroom.rs`, `damage_stage.rs`, `crate_fx.rs`. `fx.rs` (particles) is owned by `app.rs`, not `Game`, so it may use `rand::rng()`; anything whose position matters later belongs in `decal.rs`, hashed. Also `shockwave.rs`, `blast.rs`, `decal.rs`, `track.rs`, `fish.rs`, `frame_stages.rs`.

**HUD, chrome, view** (all chrome in UI points; docs/hud-and-builder-layout-design.md, docs/large-maps-follow-camera.md)
- `hud.rs` (two corner clusters; `corners()` and `result_layout()` are the one geometry the painter and every hit test read), `indicators.rs` (off-screen arrows), `minimap.rs`, `lobby.rs` (`button_rect` the one geometry; every button at least 44 pt), `qr.rs`.
- `view.rs`/`touch.rs` (bitmap-to-window mapping, `Camera`, the stick), `framing.rs` (how much world a screen shows, `MapClass`), `follow.rs` (the follow camera and the couch split), `establish.rs`, `motion.rs` (reduced motion), `margin.rs` (an arena's margins).
- `editor/` — Build mode (docs/game-editor-fusion.md, docs/map-editor-design.md): edits the `MapFile`, never live entities; input is a plain `BuilderInput`, so the dev server and tests land on the same hit tests; `chrome.rs` the one geometry table; every edit is one `EditStep` on the undo stack; no frame walks `MapFile::cells` (the kept `CellIndex`).

**Online** (`net/`, docs/online-coop-prd.md; plain synchronous code, no sockets outside `transport`, no raylib)
- `wire.rs`/`events.rs`/`codec.rs`/`delta.rs` — the protocol (postcard, quantised). `WireEvent::from_event` is an exhaustive match: a new `Event` fails to compile until mirrored or put on `NOT_SENT`. **Bump `PROTOCOL_VERSION`** on any postcard layout, enum order, kind tag or quantisation change. `encode.rs`/`apply.rs` (+ `simulation/replica.rs`) build a replica that is never `update`d and draws no RNG.
- `transport.rs` (native/web/loopback; **every socket sets `TCP_NODELAY`**), `rooms.rs` (URLs, codes, invites), `client.rs` (`RoomClient`; `connect` is the one place a client socket opens), `round.rs` (`OnlineRound`), `interp.rs`, `predict.rs` (own hull, provisional shots), `mailbox.rs`/`authority.rs` (shared by the room server and the rig so they cannot drift), `rig.rs`.

**Dev tooling** — `devserver.rs` (socket threads only queue requests, served at the frame boundary; `TOOLS` is the single table `bbmcp` advertises: a new tool is one `ToolSpec` row plus a `dispatch` arm), `capi.rs` (the web page's `ccall` surface; `capi::EXPORTS` and build.rs are checked against each other), `bin/bbmcp.rs` (stdout is protocol only - log with `eprintln!`).

## Conventions

- **Comments describe the code as it is now, not its history.** No "used to", sweep numbers or references to deleted code - git and `docs/` hold the history. A blank line must separate one item's `///` doc from the next item's.
- Rotation `0.0` = facing up. Movement is **4-direction with momentum**: `Tank::control` sets the command, `Game::drive_tank` is the whole locomotion model. `Tank::velocity` is the *commanded* cardinal vector; use `Physics::velocity` for what the body does.
- **A gameplay/feel number is a `tunables!` row**, read via `tuning().name`. Never write the global outside `tuning.rs`'s staging path, never `const X = tuning().y` (make it a fn), never recover a direction by dividing by a speed knob that may have changed since spawn. Tests use local `Tuning` values, never the global (parallel threads).
- **Seeded-replay determinism** (docs/gameplay-verification-design.md): all round randomness flows from `Game`'s one seeded `SmallRng`. Never `rand::rng()` on the simulation path (only the seed draws and the editor's cosmetic `ground_seed`); never iterate a `HashMap`/`HashSet` where the body draws RNG, spawns or breaks ties - sort first or use a `BTreeMap`; cosmetics hash from position. `Game::update` takes the RNG into a local and restores it at the end - no early return in between (a `debug_assert` checks). `determinism_tests` catches violations; probe↔probe is the bit-exact pair (the windowed game steps at the same fixed dt, but its input is live).
- Presentation modules (`game.rs`, `hud.rs`, `fx.rs`, `editor/`, `render/`) read `Game` and never mutate it; sprite layouts and per-chassis tables are commented in `lib.rs` beside their constants.
- **Raylib lives under `src/render/`** (one `cfg(feature = "render")` in lib.rs) and in `app.rs`: `render/<m>.rs` is the raylib half of `<m>.rs` under the same item names - whatever takes a draw handle, a texture, a shader or an image, plus the draw-only data nothing headless reads. An entity file keeps its state and the drawing that is generic over `canvas::Canvas`. The exceptions draw private state: `editor/render.rs` and the gated methods `TouchScheme::draw` and `DevServer::after_render`. Headless code never names `sola_raylib`; `math::{Vec2, Color, Rectangle}` are the value types on both sides.
- Every string a player reads is a `text::keys` constant; every geometry a painter and a hit test share is one function both read.
- Add a `mechanics_tests` case whenever a comment promises a mechanic.

## Seats (docs/two-players.md, docs/online-coop-prd.md §4.11)

`Game::players` is `1..=MAX_SEATS` (8) seats, a pre-init setting kept across restarts; `Game::seats` holds one tank per owner slot, seats first and enemies from `first_enemy_slot`. **Every walk goes seats in index order, then enemies**, so a one- or two-seat round's RNG stream is unchanged (`determinism_tests::the_one_and_two_seat_streams_are_pinned` - re-baseline consciously, never to go green). The couch is two seats (arrows + Space, WASD + Left Shift; none on iOS/Android); more are a room's. A wrecked seat waits for the round's end, except in a wave round of two or more, where it rolls back in with the next wave; `seats_on_field()` masks seats still in a gate lane. Detail: `docs/codebase.md`, Seats.

## Room server (`server/`; detail in docs/platforms.md, k8s/README.md)

- `bongbong-server`: the `bongbong` library headless (`default-features = false`; the image build fails if `sola` enters its graph), tokio + axum, **one instance holds every room** (one replica, `strategy: Recreate`). `GET /ws` carries every message; `/health`, `/ready` and `/metrics` are on the separate admin listener. A room is one task owning a `Game`, ticking at 60 Hz on the wall clock (`net::authority::TickClock`), sampling each seat's `net::mailbox`, sending snapshots. Difficulty follows the seat count (`tuning_patch`; one seat is the empty patch, so a room of one plays the offline round down to the bytes).
- Liveness is `/health`, **never `/ready`** (it answers 503 for the whole drain); there is **no CPU limit**, only a request (a CFS quota stutters the 60 Hz tick). It ships with the client on the version tag; every open PR gets its own server at `wss://rooms.bongbong.io/pr-<N>/ws`.
- `just run-server` (`127.0.0.1:4848`), `just run-server-dev` (plus the dev socket on 4849), `cargo test -p bongbong-server`.

## Testing & tooling (detail in docs/tooling.md)

- **Tests**: there is no project-wide suite - rendering and feel are play-tested. `cargo test --lib --no-default-features --features dev-tools` is the headless run; the raylib-backed tests (sheet decoding, `math::raylib_tests`, `corner_tests`, `bar_tests`, the thumbnail renders) need the default features. `cargo test -p bongbong-server` for `net/` or `server/`. Key suites: `mechanics_tests` (headless scenarios on tiny inline maps), `determinism_tests`, `seat_tests`, `session_tests`, the `*_tests` beside each module. No rustfmt/clippy config is checked in.
- **The game's dev server** (`just run-dev`, port 4747; `.mcp.json` registers `bbmcp`, so the `mcp__bongbong__*` tools): `restart {seed, map_toml, ...}` then `step {frames}` replays bit for bit; `screenshot` returns the frame after the latest step; call `status` (or `mode`) first. For a pixel comparison set `fx_max_particles` to 0 (particles draw from `rand::rng()`); builder screenshots differ per session (`ground_seed`). Online, every reader describes the replica. A second instance takes `BONGBONG_DEV_PORT`. The adapter caches the tool list, so a new tool needs `/mcp`. Shell: `just mcp-call <tool> '{json}'`. docs/dev-server-design.md.
- **The room server's dev surface** (`just run-server-dev`, `mcp__bongbong-rooms__*`, `just rooms-mcp-call`): the authoritative round, where a co-op bug can actually be seen - `room_open {seats}`, `seat_intent` (one intent per tick), `room_step`, `room_events`.
- **The probe** (`src/bin/probe.rs`, headless, the default way to verify mechanics): `cargo run --bin probe -- --scenario afk|advance|brake|circle|defend [...]`, greppable `ANOMALY round= seed= frame= kind=` lines, each seed a replay recipe. Extend `Game`'s public accessors, never raw world access. `just probe-fixtures` (every `maps/test/*.toml` against recorded ceilings; CI runs it): **re-baseline consciously after a deliberate AI, map or tuning change, never bump a ceiling to go green.** `just probe-fields`, `just probe-defend`, `just probe-sweep`, `just probe-waves`. `jitter` cannot tell flip-flopping from weaving - corroborate with `--log-every 1`.
- **The map linter** (`src/maplint.rs`, `cargo test --lib maplint`): `supported_maps_no_new_errors` fails on a new error class in a shipped map; `lint_map` backs the builder's CHECK and the dev server's `lint`.
- **Online**: `cargo run -- --rig --delay 80 --jitter 20 --loss 0.02` is the whole client against an in-process authority (`rig::Lockstep` for tests); `just netlab run ...`/`just netlab-suite` measure networked play against local play (netlab/README.md) - the instrument co-op feel claims are checked with.
- `--tuning knobs.json` hot-reloads a knob patch (the probe takes it too; `--print-rust` turns it into rows). Thumbnails: `mapshot`, `just thumbnails`, `just mapshot-compare`; the CPU render hash of every shipped map is pinned.

## Asset pipeline (detail in docs/tooling.md)

- Sheets are generated, not hand-drawn: Pillow scripts in `tools/spritegen/` with fixed seeds (the tanks: `tankdesign/export.py`, which also writes `src/tank_art.rs`), one spec per sheet in `docs/*_SPEC.md`. Run with `SPRITE_OUT=static`; nix's python has no pip: `nix-shell -p "python3.withPackages (ps: [ps.pillow])" --run "SPRITE_OUT=static python3 tools/spritegen/gen_walls.py"`.
- One palette (`tools/punypalette.py`, docs/PALETTE.md): run **`just check-sheets`** after regenerating; `snap()` is nearest-colour, so shade with an explicit adjacent palette step, never a computed multiple.
- The Puny World ground tileset is the one third-party exception: never edit `static/punyworld/`'s live PNGs or `_original/` (`tools/retint_ground.py` writes them). Back up sheets and generators into `static/_backup/<label>-<timestamp>/` and `tools/spritegen/_backup/...` before a sweeping art pass.
- **Never run** (historical, they regress shipped sheets): `tools/gen_shells.py`, `tools/analyze_turrets.py`, `tools/gen_tanks_candy.py`, `tools/resurrect64.py`, `tools/spritegen/gen_ground.py`, `tools/spritegen/gen_tanks.py`.

## Web / wasm (detail in docs/platforms.md)

- `wasm32-unknown-emscripten` through `sola-raylib`'s `game_loop::run` (`../sola-raylib/book/src/web.md`). `just setup-web`, `just build-web` (release into `site/dist/`), `just serve-web-dev`/`just preview-web` (dev-tools and the tuning panel; `serve-web` drops the feature).
- **fps 0 on the web** (rAF); any `fps > 0` selects a setTimeout driver that judders.
- `.cargo/config.toml`: **no `-sASYNCIFY`** (it halved the client; audio would need it back); **`-sSTACK_SIZE=4194304`** - an overflow is silent in release and surfaces as stb_image failing on a valid PNG; the `[env]` pins of `CC_/CXX_/AR_wasm32_unknown_emscripten` are required under nix.
- Shaders: `static/web/*.fs` are hand-ported GLSL ES 100 twins of `static/*.fs` - change both.
- The page's JavaScript is in `site/src/scripts/`, never inline in the `.astro` page. The canvas fills its box: never `aspect-ratio` or `object-fit` on it (raylib maps touches by the CSS box). The page talks to the game only through `window.bb*` globals read in `app.rs`. Favicons are generated (`tools/web/gen_favicon.py`).
- Production deploys on version tags; every same-repo PR gets a dev-tools preview Worker (the QA surface with the tuning panel; production never gets it). Fork PRs get no secrets by design - never "fix" that with `pull_request_target`.

## iOS (detail in docs/platforms.md, docs/ios-native-port-prd.md)

- raylib on SDL3 + GL ES 2, hand-bundled, no Xcode project; every recipe sources `tools/ios/env.sh`. `just ios-setup`, `just run-ios-sim`, `just run-ios-device`/`just run-ios-ipad`, `just ios-testflight`, `just ios-smoke` after any Xcode or runtime update.
- **iOS has no framebuffer 0**: `route_default_framebuffer` maps it onto SDL's objects, or every frame after the first render texture goes nowhere. The raylib build carries `tools/ios/raylib-sdl-highdpi.patch`. Never enable `opengl_es_20` (it links libraries Apple does not have). TestFlight builds `--release`, not `dist` (its LTO drops a symbol SDL3 needs). The simulator's GL is software - its frame times say nothing.
- No keyboard on iOS or Android (`KEYBOARD_AVAILABLE`): a RESTART button, no two-player mode.

## Android (detail in docs/platforms.md, docs/android-port-prd.md)

- raylib's `NativeActivity`, GL ES 2, one shared object, no Java or Gradle; every recipe sources `tools/android/env.sh`. `just android-setup`, `just build-android`, `just run-android`, `just android-smoke`.
- The C `main` must be in the `android/` cdylib's own objects. `android/build.rs` links `-Wl,--wrap=fopen` (without it every asset load fails silently) and `-Wl,-u,ANativeActivity_onCreate`; `nobuild` because `sola-raylib-sys` mis-parses the API level. The release key ties the app for life.

## Releases (detail in docs/platforms.md)

- `CHANGELOG.md` is the release notes: `just release-prepare [VERSION]` opens a `Release X.Y.Z` PR with the entry written from merged PRs (edit `tools/release/notes-prompt.md`, not the workflow), merge it, then `just release-tag`. The tag ships everything: cargo-dist archives (Linux, Windows), the macOS dmg, the Android APK, iOS TestFlight, the web and the room server.
- cargo-dist: `static/` ships in every archive (assets load relative to the working directory); `[dist.binaries]` must exclude `bbmcp`; regenerate with `dist generate --mode ci` without `--allow-dirty` (0.32.0 silently skips the write with it).
